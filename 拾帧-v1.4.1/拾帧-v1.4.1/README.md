# 拾帧 · Media Extractor 1.4.1

粘贴视频网页或媒体直链，查看可获得的画质和时长，下载网站提供的原始媒体，或导出指定规格的视频、音频。界面在浏览器中运行，处理工作由本机 Python 与 FFmpeg 完成。

本项目自编写代码采用 **GPL-3.0-or-later**。服务层使用 Python 标准库；抖音通过独立的平台适配器、页面结构化数据和可选浏览器策略解析；其他网站可通过独立安装的 yt-dlp 适配器提供支持。媒体探测与编码通过本机 FFmpeg / ffprobe 独立进程完成。界面和业务流程没有复制其他下载器的实现。依赖及许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 能做什么

1.4.1 默认采用 **GPU 优先插帧与编码**：通过自检的 RIFE / CUDA 在 GPU 上生成中间画面，NVENC 在显卡上编码 H.264，CPU 负责解码、音频和读写。插帧使用有容量限制的流式队列，不再将新增插帧逐张写成 PNG 后重新读取。处理硬件可选择 GPU 优先、仅 GPU 或 CPU 兼容；完成卡片显示实际路径与耗时，不把硬件名称或 120 fps 标签作为加速证据。

保留 **RTX 优先 AI 超分** 与 **拾帧 → 本地 ComfyUI 单向接口**。关闭 AI 时分辨率为上限、不放大；开启 AI 后，选择 1440p / 2160p 才会生成更大画面。超分仍使用已有的逐帧 PNG 阶段，完成后再插帧编码。配置、验证和环境冲突清单见 [AI_INTEGRATION.md](AI_INTEGRATION.md)。

- 粘贴 HTTP / HTTPS 网页地址或媒体直链，解析视频标题、时长及可用清晰度。
- 识别抖音单条作品地址、带 `modal_id` 的弹窗地址、分享短链及包含一个链接的分享文字。
- 自动解析受限时，手动选择浏览器解析，在打开的独立浏览器中登录并播放目标抖音视频。
- 查看每一步解析的结果、HTTP 状态和失败原因；可选导入仅在本机内存生效的抖音会话。
- 选择网站实际提供的画质；不会凭空增加源文件不存在的细节。
- 保存原始媒体，或导出 MP4 / AVI，视频统一使用 H.264。
- 单独提取 AAC 音频，采样率固定 **48,000 Hz**，目标比特率固定 **256 kb/s**。
- 提供任务进度、取消、结果下载和错误说明。
- 在本机运行；无需注册云服务或配置付费 API 密钥。

“原始媒体”是网站允许访问的版本。直接媒体文件可以按原字节保存；网站采用音画分离时，原始模式可能需要无损合并为 MKV 等容器。这不等同于取得上传者手中的母版，也不承诺去除网站已有的水印。指定 H.264 / AAC 的格式导出会重新编码，与原始字节保存是两个不同用途。

## 在这台 Windows 电脑启动

本次交付目录已准备独立 Python 环境，并通过 `runtime.local.json` 指向本机已经安装的 FFmpeg / ffprobe。直接双击 **`start.bat`**，默认打开 `http://127.0.0.1:8765`。保持启动窗口运行，关闭窗口即停止服务。

当前目录已安装 Playwright 1.62.0，用于调用这台电脑现有的 Chrome / Edge。浏览器解析只有在你主动选择后才会打开独立窗口。

也可以在项目目录运行：

```powershell
.\.venv\Scripts\python.exe -m framekeep --port 8765 --open
```

默认端口被占用时：

```powershell
.\.venv\Scripts\python.exe -m framekeep --port 8766 --open
```

## 在另一台电脑安装

需要 **Python 3.10 或以上**、现代浏览器，以及包含 `libx264` 和原生 `aac` 编码器的 FFmpeg / ffprobe。Windows 安装 Python 时勾选加入 PATH。macOS / Linux 同样可以运行 Python 服务；本次实际交付测试环境为 Windows。

1. 解压源码包到自己的项目目录。
2. 安装 FFmpeg / ffprobe。下载入口：[FFmpeg 官方下载页](https://ffmpeg.org/download.html)。优先选择包含所需编码器、未启用 `--enable-nonfree` 的 GPL 构建。
3. 在项目目录准备环境并指定编码器路径：

```powershell
python tools/bootstrap.py --with-ejs --with-browser --ffmpeg "C:\ffmpeg\bin\ffmpeg.exe" --ffprobe "C:\ffmpeg\bin\ffprobe.exe"
```

4. 双击 `start.bat`。

`--with-ejs` 安装 yt-dlp 推荐的额外网站依赖。省略该参数可安装更精简的基础适配器。某些网站（例如需要 JavaScript 挑战解析的网站）还需要支持的 JavaScript 运行时；本机已检测到 Node.js 24。使用 Node.js 时可在安装命令附加 `--node "C:\Program Files\nodejs\node.exe"`。以 [yt-dlp EJS 官方说明](https://github.com/yt-dlp/yt-dlp/wiki/EJS)为准。

`--with-browser` 安装 `requirements-browser.txt` 中的 Playwright 及其依赖，复用本机已经安装的 Chrome / Edge；不会下载另一份浏览器，也不会导入你的个人浏览器配置、密码或现有登录状态。该参数可单独使用，也可与 `--with-ejs` 合用。未安装 Chrome / Edge 时，先安装浏览器再重启本软件；在右上角「本地运行环境」查看是否已就绪。

如果编码器已经在 PATH 中，也可直接运行：

```powershell
setup.bat --with-browser
# 同时安装额外网站支持：
setup.bat --with-browser --with-ejs
```

软件不会修改系统 PATH，不会复制其他已安装软件的编码器文件。

macOS / Linux：

```sh
python3 tools/bootstrap.py --with-ejs
sh run.sh
```

如果只使用媒体直链适配器，项目服务自身不需要第三方 Python Web 框架。FFmpeg / ffprobe 仍负责媒体探测和编码。

## 抖音链接与登录后解析

1. 粘贴具体作品的地址或分享文字，先保留默认「自动解析」。例如 `https://www.douyin.com/user/self?...&modal_id=7670847854776159515` 会提取作品 ID，并确定标准地址 `https://www.douyin.com/video/7670847854776159515`。原始链接同时保留，用于读取原始页面；界面不会把粘贴文字改成标准地址。
2. 自动流程依次检查原始页面内的结构化数据、移动分享页数据，再尝试网站适配器。页面里无关的背景视频、播放器测试片和推荐作品不会当成目标视频。失败时展开「解析过程」查看已尝试的步骤与访问结果。
3. 如果视频在你的普通浏览器里能播放，但自动解析失败，选择「浏览器解析 · 手动登录」，或点击错误下方的「在浏览器中解析」。**1.1.0 的浏览器解析目前只支持抖音单条视频。**
4. 在新打开的独立窗口里正常登录、完成站点验证并播放这条视频。程序读取与目标作品 ID 一致的页面数据或视频详情响应，检查媒体地址后返回画质和时长。窗口在完成、取消或超时后关闭；等待期间可点击「取消浏览器解析」。页面加载后等待约 3 分钟仍未取得目标数据会提示超时。
5. 信息返回后，照常选择原文件、MP4 / AVI 视频或 AAC 音频，并开始提取。

独立窗口使用临时浏览器配置，不读取普通浏览器的个人资料。因此即使你已经在日常浏览器登录，第一次使用这里的浏览器解析仍可能需要再次登录。成功读取目标数据后，仅将 `douyin.com`、`iesdouyin.com` 及其子域的会话暂存到本地服务内存，供后续请求使用；服务重启即清除。若在「抖音访问设置」中开启「记住登录状态」，会话会额外写入本机文件并在下次启动时自动加载。浏览器自身运行时会使用临时文件，正常关闭时清理临时配置，项目不保存可复用的个人浏览器配置。

如果已有自己导出的 Netscape 格式 `cookies.txt`，也可以打开「抖音访问设置」，选择文件并点击「导入会话」。支持 UTF-8 文本，最大 256 KiB、最多 3000 条记录；程序只保留上述抖音域的有效 Cookie。选择文件不会立即导入。会话内容默认只保存在内存，不会写入任务数据库、接口响应或访问日志，页面只显示配置状态和条目数。勾选「记住登录状态」后，会话会写入 `data/sessions/douyin.json` 并在下次启动时自动加载；该文件通过 ACL 限制为当前 Windows 账户、SYSTEM 与 Administrators 可读。可在同一窗口清除会话，清除会同时删除该文件；清除会使已有抖音解析缓存失效，已经开始的下载使用自己的会话快照，可继续完成。

对上述示例作品，已验证链接识别和失败诊断；截至本次交付，**尚未在用户登录后完成该实际作品的解析与下载验证**。在普通浏览器可播放，说明你的会话有访问能力，仍需在独立窗口中实际验证平台是否提供可提取的媒体数据。各项已验证内容见 [VALIDATION.md](VALIDATION.md)。

## 编码和格式约定

### GPU 优先插帧与编码（1.4.1）

2026-10-07：GPU 流畅插帧支持单个视频最长 **3 小时（10800 秒）**、最高 **120 fps**；来源和输出分别最多 **1,296,000 帧**。30 fps 来源三小时有 324,000 帧，导出 60 / 120 fps 分别为 648,000 / 1,296,000 帧。帧数上限与 AI 超分独立。

长视频的显示时间戳持续写入当前任务目录的 `times.f64`，每帧 8 字节，通过只读内存映射逐项访问；不再把全部 FFprobe 帧 JSON 和时间戳 Python 列表同时载入内存。解码和编码各使用容量为 3 的队列，RIFE 只保留相邻参考画面，不产生插帧 PNG 序列。

GPU 插帧处理总时限为 24 小时；连续 600 秒没有进展会停止并报错。编码收尾期间继续上报状态，避免较大 MP4 写入索引时被误判为卡死。GPU 成品不沿用来源下载的 10 GiB 上限，编码前及过程中检查目标盘，少于 512 MiB 可用空间时停止；来源下载仍保持原来的 10 GiB 限制。

三小时指**输入媒体时长上限**，并不保证三小时内完成。实际用时取决于分辨率、目标帧率、显卡、素材和同时运行的其他程序。快速转换不生成新的运动画面；要执行真正 RIFE 插帧，需选择高于来源的输出帧率、「流畅插帧」，并配置通过实际自检的 RIFE/CUDA 与 NVENC。

验收结果见 [LONG_GPU_VALIDATION.md](LONG_GPU_VALIDATION.md)。AI 超分仍采用原有独立限制；本次升级范围是 GPU 流畅插帧。


默认「GPU 优先」按实际能力选择 CUDA RIFE 插帧与 NVENC 编码；所需能力不足时可使用 CPU，并在结果中说明实际使用的后端与原因。「仅 GPU」要求所需 GPU 能力可用，否则明确报错；CPU 仍承担解码、音频与读写，不表示 CPU 占用为零。「CPU 兼容」使用 FFmpeg minterpolate 和 libx264。AI 超分是独立选项，CPU 兼容不改变用户明确选定的超分提供者。

需要新增中间画面时，选择高于来源的目标帧率和「流畅插帧」。快速转换仅重复或丢弃帧；仅把编码器换成 NVENC 也不会生成新的运动细节。队列限制等待中的画面数量，使 CPU 解码、CUDA 推理和编码可以重叠工作；目前仍有主机内存与显存传输，并非全 GPU 零拷贝管线。任务结果记录插帧模型、实际插值帧数、编码器、处理耗时和总耗时。

GPU worker 复用独立 Python / Torch / CUDA 环境和 `data/rife` 外部模型；拾帧服务环境不安装 Torch，也不升级 ComfyUI 的任何依赖。GPU 就绪状态必须由推理和编码自检确认。环境检查中的「GPU · RIFE 插帧」与「GPU · NVENC 编码」是两个独立能力。页面只在选用 AI 超分或打开其设置时检测 AI 提供者，以免普通插帧任务被冷启动的 AI 检测占用 GPU 槽位。外部路径在 `runtime.local.json` 的 `interpolation_python`、`interpolation_root`、`interpolation_model` 中配置，不随源码包分发。

不同算法与编码器的速度和画面效果不能仅凭模式名比较。NVENC 使用 CQ，libx264 使用 CRF；即使参数数字相同也不等价。同素材的验证记录及实测时间见 [VALIDATION.md](VALIDATION.md)，不据短样片承诺所有视频的固定加速倍数。

### AI 超分（1.3.0）

视频解析成功后，在「AI 超分」选择「自动 · RTX 优先」、RTX 或 ComfyUI，再选择明确的输出分辨率。自动方式优先使用通过实际 GPU 自检的 NVIDIA VideoSuperRes，RTX 不可用时选择已连接的 ComfyUI。明确指定某个提供者时，失败会给出原因，不会把普通缩放当作 AI 超分。

本机 RTX 模式使用已经安装的独立 Python 3.13 / NVIDIA VFX 环境，无需启动 ComfyUI 服务；ComfyUI 模式使用本地 HTTP 接口，需要先运行 ComfyUI。双击 `start-comfy-local.bat` 可启动基础节点模式，然后在界面「AI 接口设置」检测 `http://127.0.0.1:8188` 并选择已安装的超分模型。这个启动器不加载自定义节点，不修改依赖；已经有 ComfyUI 运行时会复用现有服务。

例如 640×360 来源选择 1440p，可输出 2560×1440；选择 2160p，可输出 3840×2160。高分辨率与高帧率可以组合，但 4K 运动插帧耗时明显增加。任务先对来源画面超分，再执行所选帧率转换和 H.264 / AAC 编码；完成卡片显示实际使用的 AI、尺寸和帧率。

当前 AI 管线面向 SDR 8-bit；HDR 与带旋转显示标记的来源会给出明确提示。每次最多 18,000 个来源画面、30 分钟来源时长、20 GiB 临时帧；实际可处理长度还受磁盘、显存和 4 小时任务时限影响。超分估算细节，不能保证恢复真实纹理或所有文字。

### 常规编码与帧率

1.2.0 将「输出分辨率」「编码质量」「输出帧率」分开设置。默认保持源尺寸、使用高质量编码、跟随源帧率；原文件保存继续保留来源文件，不应用转码设置。

| 设置 | 选项与行为 |
| --- | --- |
| 输出分辨率 | 保持源尺寸，或最高 2160p / 4K、1440p、1080p、720p、480p、360p；保持比例，不放大低清来源 |
| 编码质量 | CPU：均衡 CRF 18 / medium、高保真 CRF 16 / slow、最高质量 CRF 14 / slow；GPU 使用 NVENC CQ 质量档位，两套数值不代表相同画质 |
| 输出帧率 | 跟随源视频；24、25、30、48、50、60、90、120 fps；或自定义 1–120 的整数 |
| 流畅插帧 | 提高帧率时优先用 CUDA RIFE 生成中间画面，CPU 兼容用运动补偿；快速运动、遮挡、闪光或切镜可能产生伪影 |
| 快速转换 | 通过重复或丢弃帧达到指定帧率；不增加新的运动细节，保持原播放速度 |

例如导出 120 fps：解析链接 → 选择「视频」与 MP4 → 编码质量选择「高保真」 → 输出帧率选择 120 fps → 选择「流畅插帧」或「快速转换」 → 开始提取。完成后，任务卡显示来源帧率、**实际探测的输出帧率**和实际转换方式。

降低或保持帧率时不运行运动补偿；不足三个画面的片段、无法确认帧率或视频时长的素材会使用快速转换，并在结果中说明。MP4 跟随来源时保留画面时间信息；AVI 跟随来源时按平均帧率规范化。片尾通过补足参考画面后裁切保留原视频时间范围，音视频的相对起始时间得到保留；AVI 的音频起始空隙以静音表达。

GPU 路径使用本机已配置的独立 RIFE 模型，不承诺实时插帧；CPU 兼容复用现有 FFmpeg 软件运动补偿。更高编码质量用于减少二次压缩损失，不会还原来源本来没有的细节。高分辨率 / 高帧率的处理时间和文件大小取决于素材，H.264 level 由编码器自动选择；播放性能也取决于设备。资源密集任务受队列约束，排队或处理期间都可以取消。缺少某条路径的插帧能力时会说明原因；仅 GPU 模式不会静默替换为 CPU 或复制帧。

| 导出 | 容器 / 扩展名 | 视频 | 音频 |
| --- | --- | --- | --- |
| MP4 | `.mp4` | NVENC 或 libx264 编码的 H.264，兼容性优先的 YUV 4:2:0 | AAC-LC，48,000 Hz，目标 256 kb/s |
| AVI | `.avi` | NVENC 或 libx264 编码的 H.264 | AAC-LC，48,000 Hz，目标 256 kb/s |
| AAC 音频 | `.m4a` | 无 | AAC-LC，48,000 Hz，目标 256 kb/s |
| AAC 音频 | `.aac`，ADTS 封装 | 无 | AAC-LC，48,000 Hz，目标 256 kb/s |
| 原始媒体 | 跟随网站源文件 / 合并容器 | 保留源编码 | 保留源编码 |

M4A 是 AAC 音频的一种常见封装，适合多数播放器；`.aac` 是另一种封装选择，两者的音频编码都为 AAC。MP4 更适合浏览器和通用播放。AVI 可按要求输出，但 H.264 + AAC 在部分旧式 AVI 播放器中的支持有限。

256 kb/s 是编码器的目标比特率；很短的音频、静音、容器开销和 AAC 编码行为会使探测得到的平均值略有差异。48,000 Hz 是输出采样率，不代表把低采样率原音频还原成新的声音细节。

## 本地设置与数据

运行时查找编码器的优先级为：

1. 环境变量 `MEDIA_FFMPEG` / `MEDIA_FFPROBE`。
2. 项目目录 `runtime.local.json` 的 `ffmpeg` / `ffprobe` 路径。
3. 项目目录 `tools/bin/`。
4. 系统 PATH。

Node.js 同样可通过 `MEDIA_NODE` 或 `runtime.local.json` 的 `node` 路径指定。`runtime.example.json` 是可复制的配置示例，Windows JSON 路径建议使用正斜杠。`runtime.local.json` 包含本机绝对路径，不应提交或打包到可移植源码包。

浏览器会自动查找 Chrome / Edge 的常见安装位置；也可使用环境变量 `MEDIA_BROWSER` 或 `runtime.local.json` 的 `browser` 字段指定可执行文件路径。这里指定的是浏览器程序，不是个人资料目录。macOS 等未自动发现浏览器的环境需手动指定；浏览器解析的实际验证环境为 Windows。

工作数据固定在当前项目根目录的 `data/`，不再接受外部 `MEDIA_DATA_DIR` 重定向。完成文件按任务编号保存在 `data/downloads/`；临时文件在 `data/tmp/`，可控模型和工具缓存在 `data/cache/`，任务历史在 `data/jobs.sqlite3`。从 `start.bat`、`start.ps1` 或 `打开网页-E盘缓存.bat` 打开的拾帧专用浏览器使用 `data/browser/ui/`，点击「保存文件」的副本默认进入 `data/downloads/browser/`。这与日常浏览器自身的下载设置相互独立，详见 [本地存储说明](STORAGE.md)。重启后未完成任务仍按原规则标记失败，不自动续传。

默认下载上限为每个任务 10 GiB（10 × 1024³ 字节），最多同时处理 2 个任务，排队与运行合计最多 12 个任务；解析结果缓存 1 小时。完成文件会保留，可按需清理。

软件默认绑定本机回环地址，适用于个人本机使用。自编写网络层检查初始公开 HTTP / HTTPS 地址及其重定向；本机演示地址由程序专门提供。FFprobe、yt-dlp 和独立浏览器也会自行访问网络，这些组件的全部内部跳转并未被隔离，因此应使用可信来源的链接。当前版本不是经过隔离加固的公网服务；多人部署需要补充账户、配额和网络隔离。

## 适用范围

解析成功与否取决于网站结构、源文件是否仍有效、网络、地区限制和该网站的访问要求。网站更新后可能需要升级适配器。1.1.0 提供抖音独立适配器、抖音会话导入及需要用户操作的浏览器解析；其他平台仍依赖直链 / HTML 解析与 yt-dlp 的现有站点支持。登录、验证码由用户在站点正常完成，程序不提供 DRM 解密或付费访问绕过。已失效或被站点拒绝的地址会显示失败信息。请选择自己拥有或获准下载的媒体。

更新网站适配器时，可先在独立环境验证新版本，再更新 `requirements.txt` 中的固定版本与第三方依赖记录。不要把“支持网站解析”理解为所有网站、每个视频都能下载。
