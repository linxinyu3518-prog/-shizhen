# 本地 GPU 插帧、AI 超分、单向接口与兼容记录

## 1.4.1 GPU 优先流式插帧

本版在回退后的 1.3.0 基础上增量接入 GPU 优先导出。目标是把新增中间画面的计算交给 CUDA RIFE、把 H.264 编码交给 NVENC；CPU 负责解码、时间戳、音频、调度和读写。主程序与外部 GPU worker 之间采用明确的进程协议，解码、插帧和编码通过有容量限制的队列协作，新增插帧不落地 PNG。当前仍存在主机内存与 GPU 之间的复制，并非全 GPU 零拷贝。

「GPU 优先」为默认模式；能力不足时可选用 CPU，在结果中说明原因。「仅 GPU」要求任务需要的 GPU 能力可用，否则明确报错，不静默切换 CPU。「CPU 兼容」保留 minterpolate / libx264。CUDA 插帧和 NVENC 编码分别自检，具有显卡或检测到 NVENC 名称都不能替代实际调用验证。任务结果显示实际模型、插值帧数、编码器、处理耗时和总耗时；NVENC CQ 与 libx264 CRF 不是等价质量刻度。

RTX / ComfyUI 超分继续使用 1.3.0 的来源 PNG 阶段，随后才进入帧率与编码阶段。超分、插帧同时开启时，整段超分等待和临时磁盘开销仍存在；本次没有把 ComfyUI 逐帧 HTTP 流程改造成全流程并发。CPU 兼容只约束插帧与编码，AI 超分仍执行用户另行选择的提供者。

复用 E 盘已经配置的独立 AI Python 和 `data/rife`；路径来自本机 `runtime.local.json` 的 `interpolation_python`、`interpolation_root`、`interpolation_model`。外部代码与模型不进入源码包，不向拾帧主服务 `.venv` 安装 Torch，也不修改 ComfyUI 的现有环境。迁移机器后必须分别复核 Python、Torch / CUDA、显卡驱动和模型加载自检。

上游依据：[Practical-RIFE 官方项目及模型说明](https://github.com/hzwer/Practical-RIFE)说明其推理代码及链接模型的 MIT 许可；[NVIDIA FFmpeg 硬件加速文档](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/ffmpeg-with-nvidia-gpu/index.html)说明 NVENC 编码集成。当前管线、进程通信、调度、取消与网页接口由本项目编写；RIFE 的模型架构和权重并非本项目原创。

### GPU 管线的环境冲突与报错

| 场景 | 可见问题 | 处理边界 |
| --- | --- | --- |
| 驱动与 FFmpeg NVENC 构建不匹配 | NVENC 初始化失败、编码器不可用 | 执行实际编码自检；仅 GPU 任务失败，GPU 优先说明实际使用的 CPU 路径 |
| Torch / CUDA / GPU 架构不匹配 | CUDA unavailable、no kernel image、DLL 加载失败 | 使用明确配置的独立 Python；在独立副本中验证升级，不覆盖 ComfyUI 依赖 |
| 外部 RIFE 模型版本或路径不符 | 模块缺失、权重形状不符、模型加载失败 | 同时核对模型附带实现和权重；能力检查给出原因，不把失效模型标成可用 |
| ComfyUI、RTX 超分及其他 GPU 应用并发 | 显存不足、推理突然变慢、CUDA out of memory | 应用内队列不能限制外部软件；减少同时运行任务或目标分辨率；运行中失败不能当成成功完成 |
| 4K / 120 fps 的内存与传输 | 显存峰值高、主机内存占用、传输成为瓶颈 | 使用有界队列避免无界积累；仍需同素材长片实测，不能从显卡利用率推导加速倍数 |
| 取消时管道背压 / 子进程退出 | 编码器等数据、读取线程等待、残留临时成品 | 传播取消、关闭管道并回收本任务进程；未完整完成与探测的文件不交付 |
| GPU 插帧与 AI 超分组合 | 超分 PNG 仍占磁盘，前一阶段耗时明显 | 超分阶段顺序保留；仅新增插帧改用流式传递，不宣称消除全部临时帧 |
| 色彩、时间戳与模型适用范围 | HDR 色偏、VFR 时序误差、切镜插值伪影 | 使用既有媒体限制与成品探测；兼容回退或拒绝须显示原因，不能仅显示目标帧率 |
| GPU 编码与 CPU 编码画质比较 | CQ / CRF 相同数字却有不同体积和细节 | 分别记录实际编码器、大小和验证结果，不承诺同档位逐像素一致 |

本版实际验证和时间对照见 [VALIDATION.md](VALIDATION.md)。以下 1.3.0 快照保留原日期，只描述当时的超分检查，不用作 1.4.1 性能结论。

## 使用方式

1. 刷新拾帧页面，解析视频。
2. 「输出分辨率」现在始终可以选择 1440p 与 2160p。AI 关闭时，这是输出上限，不会放大低清来源。
3. 要实际提升到 2K / 4K，选择「AI 超分辨率 → 自动选择 · RTX 优先」，再选择 1440p / 2160p。
4. 需要指定模型时，选择 ComfyUI，并在「本地接口设置」检测本机地址、选择已安装模型、保存。
5. 完成卡片分别显示请求设置和实际结果，包括使用的 AI、完整像素尺寸、真实帧率、编码和大小。

RTX 模式不要求运行 ComfyUI 服务器；它使用独立 Python 进程调用现有 NVIDIA VFX 运行库。ComfyUI 模式由拾帧主动上传画面、提交任务、轮询结果和取回 PNG。没有反向控制入口，也没有新增第三方云服务。读取响应属于该单向调用的正常返回过程。

自动选择只在创建任务时按可用性优先选 RTX、再选 ComfyUI。明确指定提供者时，或所选提供者执行失败时，不静默改用另一种算法。普通尺寸缩放不会记为 AI 成功。

## 本机环境与隔离

| 部分 | 本次核实的环境 | 隔离方式 |
| --- | --- | --- |
| 拾帧主服务 | Python 3.14.4、现有 FFmpeg 5.1.6 系列 GPL 构建 | 原 `.venv`，不导入 Torch、CUDA 或 nvvfx |
| RTX worker | Python 3.13.11、Torch 2.9.1+cu130、nvidia-vfx 0.1.0.1、RTX 5070 约 12 GB 显存 | 使用现有外部 Python，固定行 JSON 协议，持续进程复用每帧模型 |
| ComfyUI | 本机 0.33.2、Torch 2.9.1+cu130，4x-UltraSharp.pth | HTTP 回环接口，固定基础超分工作流；不安装或修改节点、依赖 |

本机运行时路径只写在未随源码分发的 `runtime.local.json`。另一台电脑可配置 rtx_python、comfyui_python、comfyui_root；路径是本机选择，不能照抄本机绝对路径。

`start-comfy-local.bat` 启动独立安装的 ComfyUI，监听 127.0.0.1:8188，使用 `--disable-all-custom-nodes --disable-api-nodes`。该启动方式仅用于本次基础超分接口，避免加载已有插件；没有删除或改动插件。要使用原有完整工作流，应运行平时使用的 ComfyUI 启动器，避免在同一端口再起一个进程。已存在本机 ComfyUI 服务时，启动器复用该服务。

RTX 实际能力由小图 GPU 推理自检确认，显卡名称存在不等于超分可用。自检结果短期缓存；首次冷加载外部 Python / Torch 可能耗时几十秒，检测期间常规导出仍可使用。

## 媒体处理行为

来源视频只解码一次；每个来源画面进行 AI 超分，保留其时间戳。最后按用户帧率设置插帧或转换，并从原媒体映射音轨，使用 H.264 / AAC 输出。中间 PNG 不发生有损视频重编码。

RTX 单级放大不超过 4 倍；超过时使用多级 AI，最终仅做尺寸对齐所需的缩小。ComfyUI 先核对模型原始输出尺寸，倍率不足时使用多级模型，级间仅缩小到下一次所需输入尺寸；最多三级，不以普通放大补足缺失的 AI 倍率。逐帧超分可能产生时序闪烁、文字或纹理变化，没有宣称它能还原真实母版。

目标不高于源高度时不执行 AI。当前 AI 管线是 SDR 8-bit RGB → H.264 yuv420p；检测到 HDR 转移特性或旋转显示标记时明确拒绝 AI，而非默默产生错误颜色或方向。常规导出功能仍保持原有行为。

同一拾帧进程同时只处理一个 AI 任务；本机其他软件的 GPU 任务不受此队列管理。每任务最多 18,000 个来源画面、30 分钟源时长，目标最多 16,777,216 像素且宽度不超过 8192。临时 PNG 超过 20 GiB、磁盘剩余不足 512 MiB，或 AI 处理超过 4 小时时会停止并清理拾帧的临时目录；单帧提供者调用限时 120 秒。

取消 RTX 任务会停止该任务独立进程。ComfyUI 取消只删除本任务仍在排队的 prompt，不发送可能影响他人任务的全局 `/interrupt`。已经开始计算的一帧可能继续完成，但不会再被拾帧作为完成视频交付。ComfyUI 自身的上传文件和预览缓存由它管理：本接口复用每个任务的上传文件名，仍可能保留最后一张输入和预览图，不能通过标准 HTTP 接口保证全部删除。

## 本次实测

使用原创合成图案与测试音，没有使用平台账号或私人媒体。

| 路径 | 来源 | 实际输出 | 检查结果 |
| --- | --- | --- | --- |
| RTX 超分 + 快速帧率转换 | 640×360，30 fps，6 帧 | 2560×1440，60 fps，12 帧 | 视频时长 0.200 秒，完整解码，AAC 48,000 Hz |
| RTX 两级超分 | 同上 | 3840×2160，30 fps，6 帧 | 视频时长 0.200 秒，完整解码，AAC 48,000 Hz |
| ComfyUI 视频 | 同上，4x-UltraSharp | 1280×720，30 fps，6 帧 | 上传、排队、推理、取回、编码全部通过，完整解码 |
| ComfyUI 两级模型 | 640×360 单张测试图 | 3840×2160 PNG | 两次模型超分后输出目标尺寸；没有普通向上缩放补齐 |
| 真实网页与浏览器下载 | 同一短测试视频，选择 2160p | AI 关闭时 640×360；自动模式时 3840×2160 | 下载所得文件再次探测，RTX HIGH、两级处理，卡片显示真实结果 |

这几段短视频的容器总时长约 0.214 秒，视频轨道为 0.200 秒；差值来自短样片 AAC 尾部，以一个 AAC 帧内的偏差验收。音频 256 kbps 是编码目标，极短素材实测平均码率可能明显不同。

RTX 两个短样片单次管线耗时约 5.0 / 6.7 秒；ComfyUI 6 帧视频约 13.6 秒、两级 4K 单图约 5.5 秒。数据包含特定素材和当时缓存状态，不可推算为长视频实时性能，也不是 RTX 与 ComfyUI 的公平速度或主观质量排名。

还检查了 AI 帧管线的 VFR、音视频不同起点、AVI 120 fps、来源帧数保持、等待与执行中取消、无效参数、HDR / 旋转拒绝。ComfyUI 通过真实本地 HTTP 模拟测试校验重定向拒绝、模型列表新旧结构、响应大小、PNG 内容、超时、取消与多级 AI 结果。网页 390 / 768 / 1024 / 1440 像素宽度无横向溢出，未出现 JavaScript 运行错误。

## 环境冲突与报错清单

下面区分已遇到并修复的问题，以及后续改动需要留意的问题；没有把假设风险描述为本机正在故障。

| 场景 | 可能表现 / 本次发现 | 本次处理及后续安排 |
| --- | --- | --- |
| 高于来源的分辨率被禁用 | **本次已遇到并修复**：1080p 或更低来源不能选 2K / 4K | 解除界面禁用；明确区分分辨率上限与 AI 目标尺寸 |
| ComfyUI API 结构更新 | **本次已遇到并修复**：模型列表格式不正确 | 同时接受旧列表结构与新版 COMBO / options；后续节点更新继续做契约测试 |
| AVI 的时间基准 | **本次已遇到并修复**：AI 帧中间件使用微秒时间基后 AVI 误报 600 fps | AVI 以目标帧率确定编码时间基，MP4 保留精细时间戳；真实 120 fps 检验通过 |
| Python 版本混装 | 在拾帧 3.14 环境安装旧 CUDA / AI 包时，可能无对应 wheel 或 DLL 加载失败 | RTX 留在独立 3.13 环境，ComfyUI 走 HTTP；后续不直接升级现有 AI 环境来解决主服务问题 |
| Torch / CUDA / 驱动 / SDK 不匹配 | CUDA unavailable、DLL load failed、invalid device function、RTX load 错误 | 检查明确使用的 Python、Torch 构建及驱动；升级先在新环境验证，避免覆盖现有模型环境 |
| 同时运行 ComfyUI 生成、RTX、其他 GPU 软件 | CUDA out of memory、进程退出、推理变慢 | 拾帧 AI 队列限一个，但无法限制其他软件；释放其他占用或降低目标，保留明确错误 |
| 首次冷加载与系统内存 | **本次观察到**：首次 Torch 导入较慢，ComfyUI 启动有较长等待 | 状态区显示检测中，自检缓存；不要把磁盘冷读误判成 SDK 未安装。长片还需关注 RAM 和页面文件 |
| 端口冲突、服务未启动、浏览器 CORS | Connection refused、地址不是 ComfyUI、8188 已占用 | 只使用回环地址；先启动服务并检测，已有服务不重复起；网页通过拾帧后端调用而非跨域直连 |
| 自定义节点或模型升级 | 缺少节点、接口输入改变、模型不支持、权重形状不符 | 本版只用基础节点并列出已安装模型，不自动装插件或权重；更新前保留独立环境和模型来源记录 |
| 取消外部任务 | 拾帧已取消但 ComfyUI 正在算的单帧继续完成 | 不调用全局中断；后续若做精准中断，需要核实服务版本支持按 prompt_id 中断并做隔离测试 |
| 磁盘和外部缓存 | 4K PNG 膨胀、No space left、服务预览持续积累 | 本机临时文件有容量限制并清理；ComfyUI 缓存清理是独立事项，不删除未知用户文件 |
| 超分与高帧率叠加 | 4K / 120 fps 运动估算耗时长，120 秒单帧或 4 小时总处理超时 | 优先分段、选择快速帧率转换，或降低目标；不得仅改帧率标签当作成功 |
| HDR、10-bit、宽色域、旋转 / SAR | 色彩发灰、亮部损失、方向或比例错误 | HDR / 旋转先拒绝 AI；SAR 在提取画面时规范化。后续增加明确色彩管理和旋转固化，不能只改尺寸 |
| ComfyUI 基础模式与原工作流 | 本次专用启动方式看不到自定义节点 | 这是启动参数限制，不是插件丢失；使用原启动器可恢复完整节点，注意不要抢占同端口 |
| 后续双向 / 第三方接口 | 重复提交、回调乱序、凭据泄漏、任务串号、跨域与本地文件暴露 | 当前不开放；设计鉴权、幂等 task_id、版本化事件、结果校验、超时与资源范围后再实现 |
| 分发包含专有运行库或模型 | 把 GPL 主程序许可误当作 SDK / 模型再分发授权 | 源码包排除外部运行库与模型；对应组件单独安装并遵守各自许可 |

## 后续扩展约定

已有 UpscaleService 负责配置快照、提供者优先级和统一结果，RTXProcess 与 ComfyClient 分别隔离执行和通信；对外状态包含 protocol_version=1。后续添加双向事件或第三方提供者时，复用任务队列与媒体管线，增加独立适配器，不让外部接口直接导入主服务内部对象或传入 shell / 任意工作流。

当前没有 ComfyUI→拾帧回调、外网地址、云密钥存储和第三方提交能力；这些是扩展点，不能在界面上标为已可用。接口参数与返回字段见 [API.md](API.md)。
